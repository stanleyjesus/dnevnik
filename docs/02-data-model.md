# Модель данных

Хранилище документное: пути вида `коллекция/документ`. Ниже — схема как она есть в артефакте. При переносе пути можно заменить, смысл полей — нет: по этой схеме идёт импорт резервной копии.

## 1. Профили и пути

| Что | Профиль `me` | Профиль `<id>` (например `p2`) |
|---|---|---|
| Тренировки | `workouts/<id тренировки>` | `workouts_<id>/<id тренировки>` |
| Настройка | `config/main` | `config/<id>` |
| Вес тела | `body/<дата>` | `body_<id>/<дата>` |
| Разбор от модели | `notes/coach` | `notes/coach_<id>` |

- Список профилей: `config/profiles` → `{ list: [{ id, n }] }`. Если документа нет, существует один профиль `me` «Мой дневник».
- `id` профиля: строчные латинские буквы и цифры, до 24 знаков; `main` и `profiles` запрещены. Новый профиль получает `p<время в base36>`.
- На устройстве (localStorage) хранятся: последний открытый профиль (`td-profile`) и черновик идущей тренировки (`td-draft` или `td-draft-<id>`).
- Права: страница спрашивает у платформы, может ли пользователь писать данные; если нет — режим «только чтение» (кнопки записи скрыты).

## 2. Тренировка

```json
{
  "date": "2025-11-10",
  "slot": "mon",
  "items": [
    { "ex": "bench", "cyc": "83/4", "sets": "90x4@3 90x4@3 90x4@2 90x4@2", "tm": 108.43 },
    { "ex": "lat_pulldown", "rng": "8-12", "sets": "57.5x11@1 55x10 52.5x12 52.5x10", "note": "…" },
    { "ex": "hammer", "rng": "8-14", "sets": "16x- 14x-", "skip": true }
  ],
  "note": "…",
  "open": true
}
```

- `id` документа — дата; вторая тренировка в тот же день получает `-2`, `-3`.
- `slot` — `mon` / `wed` / `fri`; в новом приложении ещё `d4`. Для приложения это дни 1, 2, 3 и 4 без привязки к дню недели (19 ноября 2026): идентификаторы оставлены прежними, чтобы записи не менялись.
- `open: true` — тренировка ещё идёт; в расчёты и шаблоны не входит.
- У элемента либо `rng` (двойная прогрессия, `"низ-верх"`), либо `cyc` (базовое или лёгкий день, `"процент/повторы"`).
- `tm` — расчётный максимум. Хранится у режимов «тяжёлая волна», «поддержание», «сила по запасу» и у лёгкого дня, чтобы вес не «плыл» от округлений. У обычной волны не хранится: считается как `вес / процент`.
- `skip: true` — упражнение отмечено «не делал».
- В старых записях у элемента может встретиться `rir` — одно значение запаса на последний подход; при чтении оно переносится в последний подход (`fromDoc`).
- `min` — сколько минут шла тренировка по словам атлета: целое от 5 до 300, только в приложении с днями «День N» (просьба владельца, 25 ноября 2026). Дневник спрашивает его в конце тренировки, его можно поправить в записи; по нему считается темп атлета (`docs/03`, раздел 20). В записи без ответа поля нет — она та же, что у первой версии; первая версия поле не читает.

### Запись подходов

Строка токенов через пробел: `<вес>x<повторы>[w][@<запас>]`.

| Токен | Значение |
|---|---|
| `40x12` | 40 кг на 12 повторов |
| `40x12@1` | то же, отмечен запас 1 повтор (одна цифра, 0–5) |
| `35x?` | вес есть, повторы не записаны |
| `25x-` | подход не делал |
| `20x12w` | разминочный |

В расчёты идут только подходы с числом повторов, без `w` и без `-`. Вес 0 допустим (собственный вес). Разбор и запись: `Core.parseSets`, `Core.fmtSets`, `Core.fromDoc`, `Core.toDoc`.

При завершении тренировки подходы без повторов удаляются; упражнение без единого подхода помечается «не делал».

## 3. Настройка профиля

```json
{
  "start": "2025-09-08",
  "zones": { "min": 4, "opt": 10, "high": 20 },
  "cycle": { "inc": 2, "sets": 4, "pct": { "5": 77, "4": 82, "3": 87 } },
  "method": "текст методики для разбора",
  "rir": 1,
  "bw": "gain",
  "ignore": { "forearms": 1, "abs": 0 },
  "caps": { "day": 11, "week": 100 },
  "rest": 120,
  "gear": { "barbell": { "step": 2.5 }, "g_pullup": { "n": "Подтягивания", "step": 1 }, "none": { "step": 2.5 } },
  "ex": { "…": {} },
  "program": { "…": {} }
}
```

| Поле | Смысл | По умолчанию |
|---|---|---|
| `start` | понедельник первой недели | понедельник первой тренировки |
| `zones` | границы недельного объёма | 4 / 10 / 20 |
| `cycle` | обычная волна: проценты по числу повторов, подходов, прибавка в неделю в % | 77/82/87, 4, 2 |
| `method` | методика своими словами, для разбора от модели | пусто |
| `rir` | запас по методике (0–4), к нему приводятся повторы | 1 |
| `bw` | `gain` — следить за набором веса; `track` — только записывать | `gain` |
| `ignore` | мышцы вне расчёта: `{ мышца: 1 }`. Умолчания накладываются снизу: `calves`, `abs`, `erectors` = 1. Чтобы вернуть такую мышцу в расчёт, хранится `0` | икры, пресс, разгибатели спины |
| `caps.day` | лимит подходов на мышцу за тренировку | 11 |
| `caps.week` | лимит рабочих подходов в неделю | 100 |
| `rest` | отдых между подходами в секундах (30–600), для оценки времени | 120 |
| `time` | минут на одну тренировку (только новое приложение, 19 ноября 2026): от них на «Программе» считается лимит недели; поля нет — время не ограничено. Артефакт этого поля не знает и не читает |
| `days` | тренировочных дней в неделе: 2, 3 или 4 (только новое приложение, 19 ноября 2026); поля нет — три. От него зависит, сколько дней в программе и по какому кругу идёт «следующий день». Артефакт этого поля не знает и не читает |
| `care` | (только новое приложение, 25 ноября 2026) что болит: `shoulder`, `elbow`, `wrist`, `lowback`, `hip`, `knee`. Упражнения, которые нагружают отмеченное место, получают красную пилюлю в программе и в заменах; сборку это не меняет. Неизвестные значения при чтении отбрасываются, пустой список не хранится | поля нет — ничего не болит |
| `pairs` | (только новое приложение, 25 ноября 2026) какие дни программы идут подряд: пары соседних дней по кругу: при трёх днях `"mon-wed"`, `"wed-fri"`, `"fri-mon"`, при четырёх — `"mon-wed"`, `"wed-fri"`, `"fri-d4"`, `"d4-mon"`. Действуют пары соседних дней при выбранном числе дней, если подряд не все; остальные хранятся, но не читаются | поля нет — между днями отдых |
| `gear` | шаг веса по снарядам, см. ниже | — |

Сборка настройки с умолчаниями: `Core.mergeCfg`. Страница хранит и «сырой» документ (`cfgRaw`), и собранный (`cfg`); пишется всегда сырой.

**Где это задаётся в новом приложении** (18 ноября 2026). Блока «Лимиты и методика» на экране нет — решение владельца: методика зашита в расчёт. Поля `start`, `zones`, `cycle`, `method`, `rir`, `bw`, `ignore`, `caps` остаются в документе и читаются как раньше: значения из копии артефакта действуют, новый профиль получает умолчания из таблицы. С экрана меняются только `rest` (список «Отдых между подходами» в «Тренировке» и «Программе»), `gear`, `ex` и `program`. Лимит недели для сборки выбирается в «Программе» в пределах `caps.week`.

**Встроенный справочник** (18 ноября 2026, `app/src/core/starter.ts`). Если в настройке нет ни одного упражнения — документа нет вовсе или `ex` пуст, — приложение работает с ней так, будто в `ex` лежат 63 упражнения встроенного списка, а в `gear` — снаряд `g_pullup`. В хранилище это попадает только с первым сохранением настройки: до него документа по-прежнему нет, и резервная копия отдаёт `config: null`. В настройку, где есть хотя бы одно своё упражнение, список сам ничего не добавляет. Исключение — загрузка резервной копии с экрана (решение владельца, 25 ноября 2026; раздел 5).

### Снаряды (`gear`)

| Ключ | Что это | Поля | Шаг по умолчанию |
|---|---|---|---|
| `machine`, `cable`, `barbell`, `dumbbell` | встроенные: тренажёр, блок, штанга, гантель | `step` | 2.5 / 2.5 / 2.5 / 2 |
| `g_<время в base36>` | свой снаряд | `n` (название, до 30 знаков), `step` | 2.5 |
| `none` | «Без снаряда» | `step` | 2.5 |

Свой снаряд без названия при чтении отбрасывается. При удалении своего снаряда у его упражнений поле `gear` стирается, и они ложатся по названию.

### Упражнение (`ex[id]`)

| Поле | Смысл |
|---|---|
| `n` | название |
| `m` | мышцы: `{ мышца: 1 }` — основная, `0.5` — помогает |
| `pat` | тип движения: `h_push`, `v_push`, `h_pull`, `v_pull`, `knee`, `hinge`, `iso` |
| `mode` | нет — двойная прогрессия; `cycle` — базовое по процентам; `light` — лёгкий день (тогда `of` — id базового) |
| `gear` | id снаряда или `none`. Поля нет — снаряд берётся по названию упражнения |
| `lo`, `hi` | диапазон по умолчанию, если не 8–12 |
| `uni` | правая и левая сторона записаны отдельными упражнениями; каждый подход — половина |
| `goal` | отметка: у базового `auto` / `strength` / `hold`, у многосуставной подсобки `mass` / `both` |
| `work` | известный рабочий вес, кг (необязательно). Нужен, пока упражнения нет в журнале |
| `workR` | на сколько повторов этот рабочий вес (необязательно) |
| `max` | известный разовый максимум, кг (необязательно) |
| `stop` | (только новое приложение, 25 ноября 2026) `true` — стоп-упражнение: сборка его не ставит и в заменах не предлагает, а там, где оно уже стоит, меняет на замену с теми же мышцами. Упражнение встроенного справочника с тем же названием тоже не предлагается |
| `step`, `round` | остались в данных от старых версий, **не читаются**: шаг веса — только от снаряда |

Мышцы (15): `chest`, `lats`, `upper_back`, `delt_front`, `delt_mid`, `delt_rear`, `biceps`, `triceps`, `forearms`, `abs`, `erectors`, `quads`, `hams`, `glutes`, `calves`. Группы для таблиц: верх, руки, корпус, ноги.

Как появляются id упражнений:

- исходные — осмысленные латинские (`bench`, `lat_pulldown`); такие же id у упражнений встроенного справочника: 34 — основной набор, ещё 29 — распространённые упражнения зала (`ohp`, `deadlift`, `face_pull` и другие);
- созданные в форме — `x_<время в base36>`;
- типовые из встроенного списка — `x_press`, `x_pulldown`, `x_pullover`, `x_row`, `x_ohp`, `x_raise`, `x_rear`, `x_curl`, `x_pushdown`, `x_wrist`, `x_abs`, `x_rdl`, `x_backext`, `x_legext`, `x_legcurl`, `x_thrust`, `x_calf`;
- лёгкий день — `<id базового>_light`.

### Программа (`program`)

```json
{
  "name": "Пауэрбилдинг: жим лежа",
  "focus": "bench", "others": "hold", "prio": "", "budget": 100, "lean": false,
  "since": "2025-11-17", "made": "2025-11-14",
  "slots": { "mon": [{ "ex": "bench" }, { "ex": "tbar_row", "n": 4 }], "wed": [], "fri": [{ "ex": "bench_light" }] },
  "prev": { "goals": { "bench": "" }, "program": null }
}
```

- `focus` — id базового в приоритете (программа «Пауэрбилдинг»); `others` — `hold` / `grow` для остальных базовых.
- `prio` — приоритет по мышцам: `legs`, `glutes`, `upper`, `back`, `chest`, `arms` или пусто.
- `slots` — дни программы по идентификаторам: у артефакта `mon`, `wed`, `fri`; у приложения — столько, сколько дней выбрано (`mon`, `wed` при двух; ещё `d4` при четырёх). День, которого в программе нет или который в ней пуст, приложение читает как пустой: запись этого дня, сделанная до принятия программы, шаблоном не служит.
- `budget` — выбранный лимит подходов в неделю (не больше `caps.week`).
- `lean` — добавочные подходы и новые упражнения в плане предлагаются, но выключены. То же действует при заданном `focus`.
- `strength` — программа силового режима (только новое приложение, 19 ноября 2026): каждое базовое идёт два раза в неделю, подсобка ниже рабочей зоны; вместе с заданным `focus` — сила в одном базовом: оно идёт три дня в неделю (тяжёлый день и лёгкие). Вместе с ним всегда пишется `lean`. Артефакт этого поля не знает и просто его не читает.
- `since` — с какой даты программа действует; `made` — когда принята.
- `slots[слот]` — упражнения дня; `n` — число подходов (у базового и лёгкого дня его нет: их задаёт режим).
- `prev` — отметки и программа до принятия, для отмены. В новом приложении ещё `prev.days` — сколько дней в неделе было до принятия, если число дней меняли перед ним: «Вернуть прежнюю» возвращает и его.
- `drop` — (только новое приложение, 23 ноября 2026) базовые, которыми программа пожертвовала, потому что базовых больше, чем дней: id по порядку. Пишется при принятии, если сборка что-то убрала; правка вручную сохраняет прежний список, кроме того, что атлет сам поставил в дни. Когда дней становится больше, сборка возвращает эти базовые в дни без другого базового. Артефакт этого поля не знает и не читает.
- `fit` — (только новое приложение, 19 ноября 2026) программа принята с лимитом недели, найденным по времени на тренировку: `{ time, rest, mode, days }` — минуты, отдых в секундах, режим сборки и число дней, при которых лимит найден. Пока они те же, дневник не ищет лимит больше `budget`. Артефакт этого поля не знает и не читает.
- `trim` — (только новое приложение, 25 ноября 2026) программу сократил сам дневник: тренировки по темпу атлета не влезали в выбранное время (`docs/03`, раздел 20). `{ from, to, k, time }` — подходов в неделю было и стало, темп и минуты. `trimOff: true` — у программы, которую атлет вернул кнопкой «Вернуть прежнюю» после сокращения: её дневник сам больше не сокращает. Артефакт этих полей не знает и не читает.

## 4. Вес тела и разбор

- `body`: `{ date, kg }`, id документа — дата. Онбординг приложения (25 ноября 2026) пишет сюда вес тела, введённый на шаге «Веса», с сегодняшней датой.
- `notes/coach`: `{ text, at, q }` — последний разбор, дата, вопрос.

## 5. Резервная копия

Кнопка «Резервная копия всех профилей (JSON)» в «Настройке» выгружает:

```json
{
  "format": "training-diary-backup",
  "version": 1,
  "exportedAt": "2025-11-15T08:00:00.000Z",
  "profiles": [
    { "id": "me", "name": "Мой дневник", "config": {}, "workouts": [{ "id": "2025-11-10", "date": "…" }], "body": [], "coach": null }
  ]
}
```

Это формат импорта для нового приложения. `config`, `workouts[*]`, `body[*]`, `coach` — документы в схеме выше, без преобразований; у каждой тренировки и записи веса добавлено `id`.

**Справочник при загрузке копии** (решение владельца, 25 ноября 2026; `fillStarter` в `app/src/core/starter.ts`, экран — `app/src/ui/importer.ts`). Копия первой версии приносит свой справочник: упражнения без поля `gear`, с полями `step` и `round`, и без распространённых упражнений встроенного списка. Загрузка с экрана дополняет справочник каждого профиля, в котором есть свои упражнения, — то же, что кнопки «Разложить по снарядам» и «Типовые упражнения» в «Настройке»: упражнение, которое лежит «без снаряда» только потому, что поля `gear` нет (или его свой снаряд пропал), получает снаряд встроенного списка (по id, иначе по названию; подтягивания — снаряд `g_pullup` с шагом 1 кг), а `step` и `round` у него стираются; упражнения встроенного списка, которых нет ни по id, ни по названию, добавляются. Не трогаются: названия, мышцы, режимы и диапазоны своих упражнений, выбранное атлетом «Без снаряда» (`gear: "none"`), свой снаряд, лёгкий день, журнал, программа, остальная настройка. Настройка без упражнений остаётся как есть (встроенный список подставит загрузка профиля), полный справочник — тоже, поэтому копия, выгруженная приложением, ложится как есть. Перед заменой экран называет, сколько упражнений ляжет на снаряды и сколько добавится. Запись копии в хранилище (`importBackup` в `app/src/data/backup.ts`) кладёт копию как есть: её проверяют тесты расчётов после импорта, а сверка экранов загружает записи с экрана без дополнения — так у приложения и эталона одни и те же записи.

CSV («один подход в строке», `Core.toCsv`): `date, week, day, exercise, set, weight_kg, reps, rir, flag`, где `flag` — `warmup`, `skipped`, `reps_missing` или пусто.

| `data/config.json` | настройка первого профиля, записанная «по-старому»: без снарядов, с полями `step` и `round`, которые больше не читаются |
| `data/config.p2.json` | второй профиль в начальном виде: без базовых по процентам, запас 2, принятая программа, записей нет |
| `data/config.p2.stored.json` | тот же профиль, каким его хранит приложение: общий справочник двух профилей, снаряды, названные веса, ещё одна мышца вне расчёта |
| `data/later.json` | тот же дневник неделей позже — резервная копия в формате раздела 5: запас в подходах, тренировка не в свой день недели, вес тела, свой снаряд; у второго профиля — принятая программа с приоритетом и первые тренировки |

Менять их — только через генератор и отдельным коммитом: вместе с ними меняются эталонные выводы, числа в тестах приложения и таблицы в `docs/04`. Настоящих записей в репозитории нет и быть не должно (`npm run leaks`).

## 7. Что страница ждёт от платформы

Весь доступ к внешнему миру идёт через `window.claude.use(имя)`. Чтобы запустить существующий код вне Claude, достаточно подставить объект с тем же поведением — так сделана тестовая копия (`reference/src/build.js`, блок `mock`).

| Имя | Что возвращает | Что из этого используется |
|---|---|---|
| `db` | документная база | `db.doc(путь)` → `get()`, `set(данные)`, `delete()`, `onSnapshot(next, onError)`; `db.collection(путь).limit(n)` → `get()`, `onSnapshot(next, onError)` |
| `user` | сведения о правах | `can('data.write')` → `true` / `false` |
| `sample` | запрос к модели | `sample(текст, { signal, cache, onText })` → `{ text }`; ошибки с полем `code` |
| `downloads` | сохранение файла | `save({ filename, data })`; отказ пользователя — ошибка с `code: 'declined'` |

- Снимок документа: `{ id, exists, data() }`. Снимок коллекции: `{ docs: [снимок документа], metadata: { fromCache } }`.
- `onSnapshot` вызывает `next` сразу с текущим состоянием и затем при каждом изменении; возвращает функцию отписки.
- `set` заменяет документ целиком. Частичных обновлений страница не делает.
- Если `db` недоступна, страница показывает баннер «нет связи с хранилищем» и ничего не сохраняет; без `sample` скрыт разбор, а незнакомое упражнение сразу просит отметить мышцы; без `downloads` данные копируются в буфер обмена.

## 8. Что учесть при проектировании своей базы

- Тренировок немного (сотни в год), настройка — один документ на профиль. Нормализация не обязательна; документы удобны для импорта.
- Запись подходов строкой компактна, но для запросов удобнее массив. При смене формата сохранить конвертер в обе стороны и тест на круговое преобразование.
- Идущая тренировка сохраняется с задержкой 2.5 секунды после ввода и сразу при уходе со страницы; копия лежит на устройстве и восстанавливается, если она полнее серверной.
- Настройка пишется целиком одним документом. При двух устройствах возможна гонка «последняя запись побеждает»; в артефакте это не решено.
- Справочник упражнений у каждого профиля свой; общий набор у двух профилей получается только копированием, синхронизации между ними нет.

## 9. Хранилище нового приложения

Сделано 18 ноября 2026 в `app/src/store/` и `app/src/data/`. Схема документов и пути из разделов 1–4 сохранены без изменений.

- **Где лежат записи.** На устройстве, в IndexedDB: база `dnevnik`, одна таблица `docs`, ключ — путь `коллекция/документ`. В сеть ничего не уходит.
- **Как с ним работать.** `Store`: `get`, `list` (документы коллекции по возрастанию id), `set` (заменяет документ целиком), `delete`, `batch` (несколько записей разом: все или ни одной), `watchDoc` и `watchCollection` (сразу текущее состояние, затем каждое изменение). Вкладки с одним хранилищем сообщают друг другу об изменениях.
- **Для проверок** есть такое же хранилище в памяти; оба проходят одни и те же тесты.
- **Выгрузка.** `exportBackup` собирает копию так же, как артефакт (раздел 5); файл называется `dnevnik-backup-<дата>.json`.
- **Импорт.** `importBackup` заменяет всё содержимое хранилища содержимым копии одной записью: либо целиком, либо никак. Перед этим копия проверяется (`checkBackup`): пометка формата, версия не новее 1, профили с допустимыми id без повторов, у каждой тренировки и записи веса есть свой id. Копия, не прошедшая проверку, ничего не меняет, а человек получает объяснение. Режима «дополнить» нет.
- **Загрузка в логику.** `loadProfile` читает профиль в том виде, в каком с ним работает `src/core`: тренировки через `fromDoc` и `sortW`, настройка через `mergeCfg`.
- **Настоящие записи в проект не кладутся.** Импорт проверяется на примерной копии `data/later.json`.
