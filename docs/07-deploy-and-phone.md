# Выкладка и установка на телефон

Решения владельца: приложение лежит на GitHub Pages и ставится на iPhone (18 ноября 2026); исходники и сайт живут в одном открытом репозитории, сайт собирает и публикует GitHub (20 ноября 2026).

Адрес: https://stanleyjesus.github.io/dnevnik/ — репозиторий `stanleyjesus/dnevnik`, ветка `main`. Адрес и репозиторий записаны в `app/deploy/site.json`.

До первой публикации исходников по адресу лежала версия `3711c563562f`, выложенная прежним способом — сборкой в корень репозитория. С первой отправки исходников (раздел 2, «Первая публикация») сайт публикует GitHub; какая версия на сайте сейчас, показывает `npm run live`.

## 1. Что выкладывается

- Репозиторий открытый: в нём исходный код приложения, эталон, примерные данные и документы. Личных записей в нём нет — это проверяет `npm run leaks`.
- На сайт попадает только собранное приложение — содержимое `app/dist`: страница, код, стили, шрифты, значки. 21 файл в одной папке, около 0,5 МБ.
- Записей дневника в сборке нет: они живут в браузере телефона и в сеть не уходят.
- Адрес открыт всем, кто его знает: по нему откроется пустой дневник. Странице задано `noindex` — поисковики её не показывают.

## 2. Выкладка

Сайт публикует GitHub, правила — в `.github/workflows/site.yml`:

- На отправку в `main`, в пробную ветку `try/…` и на каждый запрос на слияние идут проверки. Без браузера: в файлах и в истории нет личного, в коммитах — ни у автора, ни у того, кто внёс, ни в тексте — нет адресов почты, кроме служебных, эталон проходит свои тесты и совпадает со своей сборкой, `npm run check`. В браузере: `npm run offline` и `npm run screens`. Отправка в ветку с другим именем проверок не запускает, пока на неё не открыт запрос на слияние.
- Из ветки `main`, если все проверки прошли, приложение собирается и публикуется на GitHub Pages. Пробная ветка `try/…` сайт не трогает: она нужна, чтобы прогнать проверки на стороне GitHub до слияния.

Отдельной команды выкладки нет: обновить сайт — значит слить изменение в `main`. Согласие владельца на выкладку — это его согласие на слияние.

После публикации: `npm run live` из папки `app`, на том же коммите, что лежит в `main`. Он собирает приложение из исходников и проверяет, что адрес отдаёт ту же версию и те же файлы байт в байт, что приложение открывается на ширине телефона и ещё раз — без сети, и что в коммитах репозитория нет настоящих адресов почты.

### Настройки репозитория

Делает владелец, один раз:

- **Settings → Pages → Build and deployment → Source: GitHub Actions.**
- **Settings → Rules → Rulesets:** в `main` — только через запрос на слияние с пройденными проверками, без принудительной отправки. Сам Claude отправку в `main` не ограничивает, это делает только правило ветки.
- **Settings → Emails:** включены «Keep my email addresses private» и «Block command line pushes that expose my email».
- **Settings → Environments → github-pages → Required reviewers:** владелец. Тогда каждая публикация ждёт его подтверждения во вкладке **Actions**, кто бы ни слил изменение: правило ветки само по себе не делает слияние решением владельца.

### Подписи коммитов

Адрес автора коммита в открытом репозитории виден любому без входа: в списке коммитов и на странице коммита с `.patch` в конце адреса. Поэтому коммиты подписываются только скрытым адресом GitHub вида `…@users.noreply.github.com`; соавтор Claude — `noreply@anthropic.com`. Это проверяют шаг в `site.yml` (до публикации) и `npm run live` (после неё). Стереть адрес из уже отправленной истории можно только переписав её, поэтому подпись проверяется до первой отправки: `git config user.email`.

### Первая публикация

Сделано 23 ноября 2026 по этому порядку: проба `try/first` прошла все проверки на Linux, `main` заменён коммитом `6522b90`, сайт опубликован GitHub Actions, `npm run live` прошёл. Порядок оставлен на случай, если репозиторий придётся пересоздать.

Порядок первой публикации (делается один раз; каждый необратимый шаг — с согласия владельца):

1. Если приложение уже стоит на телефоне — сделать в нём резервную копию: адрес сайта тот же, записи лежат в браузере под ним.
2. Проверить открытый репозиторий в том виде, в каком он уйдёт: новая история из одного коммита, собранная в отдельной папке; `npm run leaks -- --история` на компьютере, где лежат настоящие записи, — «Личного не найдено»; `npm run check`, `npm run offline`, `npm run screens` проходят. В учётной записи GitHub (**Settings → Emails**) включены «Keep my email addresses private» и «Block command line pushes that expose my email»; `git log --format='%ae %ce'` в папке коммита показывает только служебные адреса.
3. Проба — это уже публикация исходников, шаг необратимый, только с согласия владельца: отправить тот же коммит веткой `try/first`. С этой минуты коммит открыт всем; удаление ветки его с GitHub не убирает. Ветка `main` и сайт при этом не меняются, а GitHub прогоняет на ней все проверки — без браузера и в браузере. Заодно видно, нет ли предупреждений об устаревших версиях действий в `site.yml`. Это первая проверка проекта на Linux; что сломается — чинится здесь и отправляется в ту же ветку заново.
4. Когда проба зелёная — в настройках репозитория переключить источник Pages на GitHub Actions, до отправки в `main`. Иначе адрес какое-то время отдаёт корень ветки с исходниками вместо приложения.
5. Отправить тот же коммит в `main`. Он заменяет прежнюю историю коммитов «Сборка …»: это принудительная отправка, прежние коммиты из ветки уходят (на GitHub они ещё какое-то время доступны по номеру коммита).
6. Дождаться зелёных проверок и публикации во вкладке **Actions**, затем `npm run live`.
7. Включить правило ветки `main`, пробную ветку удалить.

Локальный репозиторий, в котором велась работа до переезда, в открытый не отправляется никогда: в его первых коммитах лежат личные записи.

## 3. Установка на iPhone

1. Открыть адрес в Safari.
2. Нажать «Поделиться» → «На экран „Домой“».
3. Дальше открывать дневник только со значка на экране. У приложения со значка свои записи, отдельные от Safari: то, что записано во вкладке, в него не попадёт.

Почему со значка: записи сайта, открытого во вкладке, iPhone стирает, если около недели на него не заходить. На приложение с экрана «Домой» это не распространяется.

## 4. Перенос записей

1. В прежнем дневнике (артефакт в Claude): «Настройка» → «Остальные настройки» → «Данные» → «Резервная копия всех профилей (JSON)». Файл должен оказаться на телефоне: в «Файлах» или в переписке с самим собой. В репозиторий, в чат и в облачную сессию настоящую копию не класть.
2. В приложении на телефоне: «Обзор» → «Загрузить резервную копию» → выбрать файл → «Заменить записи».
3. Проверить: в «Журнале» те же тренировки, что в артефакте.

До этой проверки тренировки вести в артефакте, после — только в приложении.

## 5. Что проверить на телефоне

| Что | Где смотреть | Что должно быть |
|---|---|---|
| Записи закреплены | «Настройка» → «Остальные настройки» → «Данные», последняя строка | «Браузер обещал не стирать записи. Приложение установлено. Версия …» |
| Работа без сети | включить авиарежим, закрыть и открыть приложение | открывается с записями |
| Ввод | начать тренировку, нажать на поле повторов | экран не приближается, клавиатура цифровая |
| Резервная копия | «Данные» → «Резервная копия всех профилей (JSON)» | открывается «Поделиться», файл сохраняется в «Файлы» |
| Страница не шире экрана | «Тренировка», «Программа», «Настройка» | вбок страница не прокручивается |

Если в «Данных» написано «Браузер не обещал хранить записи», приложение работает, но надёжна только свежая резервная копия: её стоит делать после каждой тренировки, пока причина не выяснена.

## 6. Обновление

1. Изменение сливается в `main` (раздел 2). GitHub прогоняет проверки, собирает и публикует сайт; ход виден во вкладке **Actions** репозитория.
2. `npm run live` — адрес отдаёт новую версию.
3. На телефоне открыть приложение при сети. Оно само заберёт новую версию и покажет «Пришло обновление: закрой приложение и открой снова».
4. После перезапуска в «Данных» стоит новая версия.

Как это устроено: при первом открытии браузер складывает файлы приложения в запас и дальше открывает его оттуда, без сети. При каждом открытии с сетью он сверяет один маленький файл (`sw.js`); если версия другая — скачивает всё заново в новый запас, а старый удаляет. Записи дневника при этом не трогаются.

## 7. Что учтено для iPhone

- **Поле ввода не приближает экран.** iPhone увеличивает страницу при нажатии на поле с шрифтом мельче 16 px; у приложения поля были 15 px и меньше. Для iPhone и iPad шрифт в полях — 16 px (правило в конце `style.css`).
- **Список режима упражнения не шире карточки.** С шрифтом 16 px он раздвигал страницу.
- **Файл сохраняется через «Поделиться».** В приложении с экрана «Домой» скачивание файла по ссылке работает ненадёжно, поэтому резервная копия и таблица отдаются через «Поделиться» → «Сохранить в Файлы».
- **Предупреждение во вкладке.** Если дневник открыт в Safari, а не со значка, в «Данных» написано, что такие записи iPhone сотрёт, и как поставить приложение.

## 8. Что проверено и что нет

Проверено на компьютере, в Edge (`npm run offline`, `npm run screens -- --шрифт-айфона`, а для выложенного адреса — `npm run live`): приложение работает в подпапке адреса и с кэшем на 10 минут, как на GitHub Pages; открывается без сети; обновление доходит и не трогает записи; с шрифтом 16 px в полях ни один экран не становится шире 390 px.

Не проверено — нужен настоящий iPhone: установка со значком, закрепление хранилища, «Поделиться» для резервной копии, выбор файла копии, отсутствие приближения при вводе, вид на экране с вырезом.

Проверено при первой публикации 23 ноября 2026: проверки и публикация на стороне GitHub (Linux, Node 22, Chrome без окна) проходят; проверки без браузера идут около минуты, работа без сети и сверка экранов — около 13 минут; сборка на Linux байт в байт совпадает со сборкой на Windows.
