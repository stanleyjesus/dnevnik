# Тренировочный дневник — контекст проекта

Вводная для Claude Code: что за продукт, для кого он, какие решения уже приняты и что нельзя сломать. Здесь только то, чего не видно из кода. Подробности — в `docs/` (читать по задаче, список ниже), точное поведение — в `reference/src/`.

## Что это

Дневник силовых тренировок: веб-приложение, которое ставится на телефон и работает без сети (`app/`). Записи лежат только на устройстве, запросов к нейросети нет. Первой версией дневника была одна HTML-страница — артефакт в Claude; её код лежит в `reference/` как эталон, с которым сверяется приложение. Задача — развивать приложение: править код, добавлять и менять функции.

Репозиторий открытый. Личных записей в нём нет и быть не должно — см. «Личное и открытый репозиторий».

Дневник делает четыре вещи:

1. Хранит тренировки: упражнения, подходы, вес, повторы, запас до отказа.
2. Строит план следующей тренировки по правилам атлета и предлагает поправки с объяснением.
3. Считает недельную нагрузку по мышцам и показывает, что отстаёт.
4. Собирает и перестраивает программу под цель в рамках лимитов атлета.

## Для кого

Дневник ведёт один человек — владелец проекта. Он принимает решения о методике и о продукте: его согласие нужно для каждого изменения правил. Выкладку — слияние в `main` — Claude делает сам, когда владелец принял содержание и все проверки прошли (решение владельца 24 ноября 2026). В дневнике может быть несколько профилей, у каждого свои записи и настройки. Профиль идёт по методике по умолчанию (в приложении — методика под цель, запас 1 повтор) или со своей: например, с запасом 2 повтора.

## Методика по умолчанию — исходные правила, молча не менять

С 24 ноября 2026 (решение владельца) в приложении — с днями «День N», так открывается любой профиль — действует методика под цель (`app/src/core/rules.ts`, `docs/03-methodology-and-algorithms.md`, раздел 15):

- «Базовое» — роль в программе: по проценту от расчётного максимума идёт только базовое в силовой роли, которую ставит цель «Сила» или «Гибрид». Тяжёлый день — сила по запасу: 3×4 одним весом на 83%, вес на следующую неделю решает запас в последнем подходе (запас от 4 — сразу несколько шагов, не больше 10%; шаг больше 5% веса — сначала повторы 3×5, 3×6); лёгкий день — 3×8 на 75%, у становой 3×6 на 79%; среднего дня нет (25 ноября 2026); у изоляции в силовой роли — 3×6 на 79% и 3×10 на 71%; во всех этих днях запас около 2 («Новая схема», 24 ноября 2026), лёгкий день сдвигается на шаг по своему запасу; поддержание — 3×4 на 83% от максимума, который не растёт. Волны 77 → 82 → 87 нет; волна, записанная в профиле, остаётся в данных.
- Всё остальное, в том числе базовое в «Массе», идёт по двойной прогрессии, и каждый подход ведётся отдельно от соседних; запас — 1 повтор (RIR 1), в многосуставных со свободным весом — 2 (25 ноября 2026). Взял верх диапазона — в этом подходе в следующий раз следующий вес. Ниже нижней границы — вес ниже.
- Диапазон по типу упражнения: многосуставные и базовые — 6–10 повторов, изоляция — 8–12; ширина = шаг веса в % / 2.5, не уже 4 и не шире 8, чтобы после прибавки веса нижняя граница была по силам; свой диапазон упражнения остаётся.
- Порядок в тренировке: первым — то, что важнее для цели (движение цели, базовое дня, мышцы в приоритете); многосуставные — до изоляции; соседние упражнения — на разные мышцы, если можно иначе. Сборка расставляет дни черновика, в «Вручную» порядок атлета.
- Вес в подтягиваниях — общий: тело плюс отягощение. С гантелями пишется вес одной гантели.

С таблицей дней эталона — в эталонных тестах и общих сценариях сверки экранов — действуют правила первой версии:

- Жим лежа, жим ногами, подтягивания («базовые») — волна от расчётного максимума: 77% 4×5 → 82% 4×4 → 87% 4×3, по кругу; максимум +2% в неделю.
- Остальные упражнения — независимая двойная прогрессия с запасом 1 повтор; нижняя граница диапазона не меньше 8, ширина = шаг веса в % / 2.5.

Профиль может вести все упражнения на двойной прогрессии, без базовых по процентам, и со своим запасом — например, 2 повтора.

## Решения владельца по ходу работы

Каждое — требование, а не пожелание. «Ноль» и «поровну» читаются буквально.

- Не больше 11 подходов на мышцу за тренировку и не больше 100 рабочих подходов в неделю. Учитывать в поправках плана и при сборке программы.
- Поправки появляются прямо в плане тренировки, а не в отдельном разделе советов.
- Программа по умолчанию показывается собранной «Равномерно». «Равномерно» — буквально: ни одна мышца не забирает нагрузку у остальных (разброс около двух подходов).
- Приоритетная группа мышц берёт больше, но не настолько, чтобы остальные проседали: сейчас в полтора раза выше остальных.
- Икры, пресс и разгибатели спины в расчёте подходов не участвуют: при сборке у них ноль. С днями «День N» — и предплечья (25 ноября 2026): хват идёт им половиной подхода в тягах, подтягиваниях, становой и сгибаниях на бицепс. Прибавить им можно только руками — кнопкой «+» у мышцы.
- У каждой мышцы в программе — кнопки «убавить / прибавить подход»; дневник сам решает, какое упражнение менять. Выбранный лимит недели — общий запас: рядом всегда видно, сколько подходов свободно.
- Везде, где показан недельный объём мышцы (программа — «Сейчас» и «Станет», недели по факту), видно, сколько его даёт подсобка (масса) и сколько базовые по процентам (сила). С днями «День N» (26 ноября 2026) — общее число и в скобках только силовые: «11.5 (сила 5.5)»: растят мышцу все подходы с малым запасом, а не только «масса» (`docs/03`, раздел 3).
- Каждая мышца тренируется больше одного раза в неделю.
- У каждого упражнения в программе можно выбрать замену на те же мышцы.
- Шаг веса считается только по снаряду, в котором лежит упражнение. Своего шага у упражнения нет. Исключение сделано снарядом: «Подтягивания», шаг 1 кг.
- Упражнения без снаряда видны поимённо.
- Новое упражнение — только название и снаряд. Мышцы дневник определяет сам; справочник мышц на виду не нужен.
- В «Настройке» на виду только упражнения: снаряды и известные веса. Остальное — в одной свёрнутой строке.
- В настройке можно указать рабочий вес или разовый максимум; дневник берёт их, пока упражнения нет в журнале.
- Не перегружать экран текстом: пояснения сборки свёрнуты по умолчанию, подписи — в одну-две строки.
- Нужна оценка времени тренировки с выбором отдыха между подходами. С днями «День N» (25 ноября 2026) отдых не выбирается: дневник ставит его каждому упражнению сам — тяжёлый день и поддержание 5 мин, лёгкий и средний день 3 мин, многосуставные со свободным весом 2 мин 30 с, остальные многосуставные и изоляция 2 мин; на этом отдыхе стоит и оценка времени (`docs/03`, раздел 17). Разминка в оценке времени — по типу упражнения (выбор владельца 25 ноября 2026): минута на подготовку и 1 мин 30 с на разминочный подход — тяжёлый день и поддержание 4, лёгкий день и базовое на двойной прогрессии 2, первое упражнение на мышцу 2 со свободным весом и 1 в остальных, мышца уже работала — 0; в идущей тренировке у упражнения — строка «Разминка, кг: …» с этими подходами: доли первого рабочего веса 40 / 60 / 75 / 90% × 6 / 4 / 2 / 1, 50 / 80% × 6 / 3, 70% × 5 (исследования и тренерская лесенка, `docs/03`, раздел 17).
- Нагрузка по мышцам — светофором и на фигуре человека.
- Режим «Пауэрбилдинг»: одно базовое в приоритете — два дня на силу (4×4 по запасу и лёгкий день) и один день на массу; остальные базовые на поддержании, остальные мышцы — как для массы.
- Второй день сразу всем базовым не нужен: он забрал бы объём у подсобки.
- Справочники упражнений двух профилей должны дополнять друг друга.
- Блока «Лимиты и методика» в «Настройке» нет (18 ноября 2026): методика для расчёта диапазонов, весов и прогрессии зашита в алгоритм и проявляется в программе и в поправках плана, а не в полях настройки. Значения, уже сохранённые в профиле, действуют как раньше.
- Справочник упражнений не бывает пустым (18 ноября 2026): в профиле без упражнений сразу лежит встроенный список — основной набор и распространённые упражнения зала, все разложены по снарядам.
- Программа, собранная с нуля, сама получает базовые из справочника: по одному в день, первым упражнением. Пауэрбилдинг предлагается для каждого базового справочника, даже если его ещё нет в программе (19 ноября 2026). Исключение — «Масса» (25 ноября 2026, ниже): там базовые с нуля сами не встают.
- Среди сценариев сборки есть отдельный силовой режим — это не пауэрбилдинг (19 ноября 2026). Правила выбраны из двух посчитанных вариантов: каждое базовое два раза в неделю — тяжёлый день 4×4 по запасу и лёгкий день 3×4 на 78%; подсобка целится на два подхода ниже рабочей зоны; лимит недели в этом режиме по умолчанию 80. Это осознанная цена силового блока: в остальных режимах второй день по-прежнему только у приоритетного базового. С днями «День N» его место заняли цели «Силы» (24 ноября 2026, ниже); силовой режим остался с таблицей дней эталона.
- Сценарий сборки выбирается целью, а не одним длинным списком (19 ноября 2026): кнопки «Масса», «Сила», «Гибрид» (это пауэрбилдинг), «Вручную» и под ними один уточняющий список, который зависит от цели, — мышцы в приоритете, базовое в приоритете или «Все базовые». Предлагались три блока (цель, мышца, силовое движение); второй и третий — один список, чтобы на экране не было двух выборов, из которых действует один. Расчёт от этого не меняется.
- Под целью «Сила» можно выбрать одно базовое (19 ноября 2026): оно идёт три дня в неделю — тяжёлый день 4×4 по запасу и два лёгких дня 3×4 на 78%. Три дня выбраны из двух посчитанных вариантов, чтобы режим отличался от гибрида: там движение идёт два дня и есть день «на массу». Остальные базовые — раз в неделю (тот же переключатель, что в гибриде), подсобка и лимит недели 80 — как в силовом режиме. Число дней по стажу не выбирается: исследования такой связи не дают. С днями «День N» — цель «Силы» с днями новой схемы (24 ноября 2026, ниже).
- Лимит недели можно не выбирать, а получить от времени на тренировку (19 ноября 2026): на «Программе» список «Время на тренировку» (не ограничено, от часа до двух, с 25 ноября 2026 — до 2 ч 30 мин), дневник берёт самый большой лимит, при котором самая длинная тренировка укладывается; выбор хранится в профиле. «Не ограничено» — как раньше; лимит, выбранный вручную, время снимает. Умолчаний «по стажу» нет: прямой связи объёма со стажем исследования не дают. С днями «День N» (25 ноября 2026) списка «Подходов в неделю» нет: подходы дневник считает от времени, дней и цели, а лимит недели 100 (под «Силой» без выбранного времени — 80) остаётся в методике и виден в счётчике свободных подходов.
- Дни программы — примерно равные по длине (25 ноября 2026): с днями «День N» при любом числе дней, пока самая длинная тренировка дольше самой короткой больше чем на 10 минут, сборка переносит упражнение, подход или меняет упражнения днями; объём недели тот же, у мышцы остаётся не меньше двух дней (`docs/04`, раздел 3.8, правило 8). Под «Силой» время подходами по-прежнему не заполняется: подсобка — 8 подходов в неделю (выбор владельца тем же днём, «8, как сейчас»).
- Методика под цель (24 ноября 2026, вопрос сборки 9): в приложении проценты, повторы и прибавку дневник считает от цели программы и типа упражнения — по исследованиям, а не по исходной волне (`docs/03`, раздел 15). В «Массе» базовое идёт по двойной прогрессии 6–10; по проценту — только в силовой роли «Силы» и «Гибрида»: тяжёлый и лёгкий день (с того же дня — по «Новой схеме», ниже), поддержание 3×4 с прежним весом. Многосуставные — 6–10, изоляция — 8–12 (тем же днём вместо 10–15: для роста разницы нет, подход короче), запас 1; ширина диапазона — от шага веса. Двойная прогрессия — независимая: каждый подход ведётся отдельно и каждый стимулирующий. Списка «Режим» у упражнения нет: роль задаёт цель. Ответы по пункту 8 (что идёт под «Силой») введены тем же днём — следующий пункт.
- Цели «Силы» и «Гибрида» (24 ноября 2026, вопрос сборки 8): «базовое» — роль в программе, по проценту идёт только цель. Под «Силой» — «Пауэрлифтерская тройка» (приседания, жим лежа, становая: каждое — тяжёлый и лёгкий день; от трёх дней в неделе) или одно из восьми движений — жим лежа, приседания со штангой, жим ногами, подтягивания, становая тяга, ягодичный мост со штангой, жим штанги стоя, бицепс со штангой стоя: тяжёлый, лёгкий и средний день, не больше трёх дней, у изоляции два дня; мышцам цели в полтора раза больше. Под «Гибридом» — те же восемь: два дня на силу и день на массу. «Все базовые» нет. Остальные базовые под «Силой» — обычные многосуставные 6–10; переключатель «Остальные базовые» и список «Без базового» — только в «Гибриде». Цели, которой нет в справочнике, сборка берёт из встроенного; роль живёт в принятой программе, справочник не переписывается (`docs/03`, раздел 15.4; `docs/04`, раздел 3.3в).
- «Новая схема» тяжёлого и лёгкого дня (24 ноября 2026): владелец попросил построить дни силовой роли с нуля по исследованиям, забыв прежние числа, и из двух посчитанных вариантов выбрал этот. Дни отличаются повторами: тяжёлый — 3×4 одним весом на 83%, вес решает запас в последнем подходе, как раньше; лёгкий — 3×8 на 75%; средний — 3×6 на 79%, только у «Силы: <движение>» (за тяжёлым днём по кругу — лёгкий, за ним средний); у изоляции — 3×6 на 79% и 3×10 на 71%. Во всех днях запас около 2, поэтому лёгкий и средний идут в объём мышцы целиком. Лёгкий и средний день — ровно доля от расчётного максимума с первой недели, и у цели, которой в журнале ещё нет; ограничение первой версии «не легче самого лёгкого веса в журнале» — только там, где в вес входит тело (выбор владельца тем же днём). С таблицей дней эталона — прежние 4×4 и 3×4 на 78% (`docs/03`, раздел 15.5).
- Порядок упражнений в дне (24 ноября 2026, вопрос сборки 13): первым — то, что важнее для цели: движение цели «Гибрида» и «Силы: …» (тяжёлый или лёгкий день), базовое дня, затем упражнения мышц в приоритете и упражнение «на массу»; многосуставные — до изоляции; соседние упражнения — на разные мышцы, если можно иначе. «Сначала верх, потом низ» исследования не подтверждают — его нет. Сборка расставляет дни черновика и пишет в свёрнутой заметке, что переставила; в «Вручную» порядок атлета (`docs/03`, раздел 15.3).
- Максимум по подходам (24 ноября 2026): в приложении максимум тренировки в истории упражнения у всех упражнений, и у базового по проценту, — лучший подход по Эпли от повторов плюс запас, а не «вес / процент»: тот не видит повторов и запаса, и тренировка тяжелее с теми же «повторы плюс запас» показывала спад. От него рекорды, статус, индекс силы и поправки «Плато» и «Откат»; расчётный максимум плана, от которого считается вес по проценту, прежний (`docs/03`, раздел 15.1, пункт 9).
- Время, базовые в «Массе», число упражнений (25 ноября 2026, отложенная задача о времени): с выбранным временем в «Массе» и «Гибриде» время заполняется подходами — общий уровень мышц растёт выше 10, пока каждая тренировка укладывается во время и неделя — в лимит, до верха рабочей зоны (уровень до 18, с мышцами в приоритете — до 12, чтобы приоритет до 18 оставался в полтора раза выше); под «Силой» подсобка по-прежнему ниже рабочей зоны. С выбранным временем в тренировке не больше десяти упражнений (пара сторон — одно), на мышцу — не больше двух упражнений, где она основная (у мышцы в приоритете — трёх), второе упражнение на мышцу в тот же день — только когда в первом уже три подхода; без времени — девять, как было. В «Массе» — и с мышцами в приоритете, и «Всем поровну» (уточнено владельцем тем же днём) — сборка с нуля базовые справочника сама не ставит: упражнения подбираются по мышцам из остального справочника; в «Силе» и «Гибриде» — как было. Лимит 11 подходов на мышцу за тренировку сходится с исследованием (Remmert и соавт., 2025); число упражнений исследования не задают — это правило дневника (`docs/04`, раздел 3.8, правило 7).
- Румынская тяга (23 ноября 2026): разгибатели спины в ней помогают (½), а не основные, — сборка больше не убирает её из профиля, где разгибатели вне расчёта. «Ноль» у мышц вне расчёта читается как «сборка им подходов не выделяет»: косвенные от упражнений, где они помогают, остаются. Заметка сборки называет настоящую причину, почему уровень ниже рабочей зоны, и не советует увеличить лимит, когда подходы свободны. В приоритете можно выбрать группу «Плечи» — три пучка дельт. Кнопки «+ Снаряд» нет: шаг меняется у снарядов, которые есть. Баланс движений дневник не считает: нет ни замечаний «В программе нет …», ни карточки «Баланс движений», ни поправок ради него. Упражнений в дне — от времени на тренировку: с выбранным временем сборка заполняет день, пока он укладывается в это время, — потолка «девять упражнений в дне» нет, больше времени — больше упражнений (с 25 ноября 2026 — не больше десяти, ниже), а второй день каждой мышце ищется с первого шага; при «не ограничено» — девять, как в эталоне. В тренировке одно базовое по процентам: когда базовых больше, чем дней (при двух днях — три базовых), лишнее уходит из программы с заметкой «Не в программе», а каким базовым жертвовать, атлет выбирает в списке «Без базового» над днями; приоритетное не уходит, выбор хранится с принятой программой, а когда дней становится больше, убранное возвращается само. Остальные ответы владельца на разбор вопросов сборки (23 ноября 2026) — в `docs/05-features-and-backlog.md`, раздел 4.
- Справочник при загрузке копии (25 ноября 2026): копия первой версии приносит свой справочник без снарядов, и встроенный после загрузки пропадал. Загрузка с экрана сразу дополняет справочник каждого профиля встроенным — то же, что кнопки «Разложить по снарядам» и «Типовые упражнения»: упражнения «без снаряда» — на снаряды встроенного списка, недостающие из 63 — добавляются; свои упражнения, журнал и программа не меняются (выбор владельца из трёх: дополнять сразу, спрашивать галочкой, оставить кнопками; `docs/02`, раздел 5).
- Онбординг для новичка (25 ноября 2026): пока в профиле нет ни тренировок, ни программы, приложение с днями «День N» открывается мастером на весь экран без вкладок — «С чего начнём?» (собрать программу, своя программа, файл копии), цель и время, дни программы с заменой упражнений и «Принять» (у программы, которую собрал дневник, только «Заменить» со списком замен под кнопкой: порядок и подходы уже посчитала сборка, поэтому стрелок, «−/+», «убрать», пометки «новое» и строки «В день» нет; тем же днём так же и по виду точно как в онбординге — в черновике вкладки «Программа» при любой цели, кроме «Вручную»: пометок «перенос» и «+N подходов» там тоже нет, полоса слева — только у замены, «было N» в заголовке дня нет, подходы мышце — кнопками у мышцы; дни на этом шаге — карусель: листаются вбок, а не вниз, над ними полосы дней; открытый день по центру, края соседних связаны с ним перемычкой, как в присланном образце; шапки приложения в мастере нет; тексты мастера короткие, на шагах цели и программы — только выбор и карточки дней; на «Программа готова» — дни каруселью и фигура с нагрузкой мышц за неделю — просьбы владельца тем же днём), веса, «Программа готова» с первой тренировкой; «Назад» и «Пропустить», вопроса о стаже и фильтра по снарядам нет; после «Пропустить» в пустом «Обзоре» только две кнопки — «Собрать программу» (снова мастер) и «Загрузить резервную копию». На шаге весов шаг веса снарядов программы атлет вводит сам: поля пустые, рядом подсказка «обычно N кг». Пустое упражнение со штангой или гантелями получает старт по похожему названному: жим лежа 100 кг на раз → жим гантелей лежа ≈ 30 кг (доли семей — `docs/03`, раздел 15.6; две гантели ≈ 83% штанги — исследование, остальное — тренерские правила с запасом вниз); тренажёры и блоки не оцениваются — вес на стеке у каждой модели свой. На первом экране мастера есть и «Вставить программу текстом»: дни и упражнения из заметки, незнакомые названия атлет выбирает сам или добавляет новым упражнением со снарядом.
- Упражнение, которое не успеваешь, и время по факту (25 ноября 2026, просьба владельца после разбора «человек систематически не делает одно упражнение»): с днями «День N» упражнение, не сделанное в двух последних тренировках дня, уходит из плана поправкой «Не делал два раза» — дневник переносит его в день, где хватает времени, иначе раздаёт его подходы упражнениям на ту же мышцу, иначе убирает с заметкой о причине и объёме мышцы; перенос и раздача пишутся в принятую программу, когда тренировка закончена без него. В конце тренировки дневник спрашивает, сколько она шла, и множит свою оценку времени на темп атлета — медиану «названное / посчитанное» по последним пяти ответам. Тем же днём (владелец: «автоматически … программу с урезанным объёмом»): когда программа собрана под выбранное время, а с темпом атлета (от трёх ответов) самая длинная тренировка в него не влезает, дневник после тренировки сам принимает программу той же цели под то же время с темпом и пишет об этом; «Вернуть прежнюю» отменяет и больше её не сокращает; сам дневник только сокращает; «Вручную» и без времени не трогаются; прибавки плана сверх выбранного времени не включаются (до 26 ноября 2026 предлагались галочкой) (`docs/03`, раздел 20; правила — тренерские).
- День программы — это просто «День 1, 2 … N», привязки к дню недели нет; дней в неделе два, три или четыре — число выбирается на «Программе», у каждого профиля своё, и программа под него пересобирается (19 ноября 2026). Прежние записи не трогаются: идентификаторы `mon` / `wed` / `fri` остались днями 1–3, четвёртый день — `d4`. Куда ставить массу у гибрида при двух и четырёх днях, оставлено на усмотрение разработчика: при четырёх — один день, самый дальний от тяжёлого; при двух — в лёгком дне.
- Выводы аудита методики (25 ноября 2026): владелец принял выводы 2–11 аудита «Аудит методики сборки программ» (24 ноября 2026), вывод 1 — время заполняется подходами — отдельной задачей; всё с днями «День N» (`docs/03`, раздел 16). Предплечья вне расчёта по умолчанию и хват им — половина подхода в тягах, подтягиваниях, становой и сгибаниях на бицепс (оба варианта сразу, выбор владельца). Из упражнений на ту же мышцу раньше — растянутые варианты: сгибания ног сидя, трицепс из-за головы. Ягодицы в приседаниях — основные. В «Гибриде» остальные базовые по умолчанию — как подсобка, «Растут как раньше» — выбором; «Поддержания» в переключателе нет (владелец, 25 ноября 2026: поддержание не растёт, вариантов два). Тяжёлый день: запас от 4 — несколько шагов (около 2.5% на повтор запаса сверх двух, не больше 10%), шаг больше 5% веса — сначала повторы, карточка просит отметить запас. Лёгкий и средний день сдвигаются на шаг по своему запасу: 4 и больше два раза подряд — выше, 0 — ниже. Лёгкий день становой — 3×6 на 79% (выбор владельца вместо 3×8); «Сила: <движение>» у всех движений — два дня, тяжёлый и лёгкий, без среднего (владелец спросил, зачем средний день: исследований, что три дня лучше двух, нет). Запас 2 в многосуставных со свободным весом, в тренажёрах и изоляции — 1. Раз в четыре недели — поправка «Проверка запаса»: последний подход одного изолирующего упражнения до отказа. Вывод 8 без выбранного времени: в дне от шести упражнений упражнение в два подхода отдаёт их другому на ту же основную мышцу (одно на 3–4 подхода вместо двух по два), когда баланс недели от этого не хуже; с выбранным временем — правила времени.
- Плато по тренду (26 ноября 2026, разбор «Сила, масса и плато», рекомендации 1 и 2): с днями «День N» «Плато» и «Откат» двойной прогрессии — не «три тренировки без рекорда», а два окна по 4 недели: плато, когда за последние 4 недели ни лучший подход, ни один подход дня не прибавил больше 0.5% против 4 недель до них и вес в диапазоне не вырос; откат — лучший подход слабее прежнего больше чем на 5%. Каскада нет: считаются только тренировки после последнего снижения веса в дне (сброс, свой сброс атлета, шаг вниз), в каждом окне — от двух. Тренерское правило, порога в исследованиях нет (`docs/03`, раздел 21). Что делать (тем же днём, рекомендации 3–5): при «Плато» вес не снижается — сначала «Проверка запаса» последним подходом до отказа (если за 8 недель её не было), потом +1 подход, когда основной мышце по программе меньше 12 в неделю, через 8 недель без прибавки с проверенным запасом — замена на упражнение на те же мышцы (предлагается выключенной); −10% — только «Откат» и «Разгрузка». «Мало объёма» прибавляет подход и стоящему упражнению. После снижения веса карточка просит отметить запас (`docs/03`, раздел 21.1). Статус «застой» и «откат» на «Прогрессе» — по тому же тренду; где тренда не видно — как раньше (`docs/03`, раздел 21.2).
- Лишнее с экранов (25 ноября 2026): с днями «День N» вкладки «Советы» нет — поправки дневника и так в плане тренировки, программа корректируется по результатам; на «Обзоре» сверху только «Тренировок записано» и «Индекс силы», блока «Требует внимания» нет; на «Тренировке» нет выбора «Вариант плана» — план всегда с поправками дневника (с 26 ноября 2026 — без галочек, ниже). Подсказки «Советов», которых больше нигде нет (темп веса тела, незаписанные повторы, провал повторов между подходами, разница сторон), владелец решил убрать, а не переносить. С таблицей дней эталона всё как в артефакте (`docs/01`, раздел 7).
- Тренировка без ориентиров, шапка, фигура карточкой (26 ноября 2026, просьбы владельца): с днями «День N» в идущей тренировке — после «Начать тренировку» — у упражнения только вес, повторы, запас, «не делал», «+ Подход», разминка и заметка: нет диапазона повторов, «прошлый раз», прошлых результатов и ориентиров, стрелок «выше / ниже», «убрать» и поправок дневника с «Вернуть по правилу» — каждая тренировка самостоятельная, чтобы атлет не гнался за прошлым результатом, а план выставляет дневник по алгоритму. Тем же днём (владелец: «берём её тоже») — и до старта: карточки «Что дневник меняет в плане и почему» с галочками нет, снять поправку нельзя, прибавки сверх выбранного времени не включаются; нет «Начать с пустого листа» и целевых повторов у весов плана («8+»). Нагрузка мышц на «Обзоре» и «Мышцах» — значком зоны без подписи, с одной легендой; в «Журнале» подходы раскрываются нажатием, рядом с упражнением — «рекорд», «застой», «откат» (правила статуса «Прогресса»); на «Прогрессе» в истории упражнения — только лучший подход; стрелка выпадающих списков — с отступом от края. Дни текущей программы и черновика на «Программе» — карусели, как в онбординге; на «Мышцах» у «Подходов на мышцу по неделям» нет пояснения, группы мышц — карточки карусели с последними четырьмя неделями, блока «На чём основаны оценки» нет. На всех экранах в шапке нет названия приложения и «записи на устройстве». Фигура мышц — одна карточка: сначала вид спереди, нажатие переворачивает на вид сзади. На шаге «Веса» онбординга шаг веса, упражнения с весом тела и веса упражнений — отдельными карточками (`docs/01`, раздел 14).
- Памятка (26 ноября 2026, просьба владельца): с днями «День N» последний шаг онбординга и экран поверх тренировки сразу после «Начать тренировку» — «Памятка»: растягивай мышцу, где упражнение это позволяет (исследования), опускай вес под контролем 2–3 секунды (тренерское правило), в конце подхода считай запас и записывай его. У каждой карточки своя анимация на SVG без файлов и сети; закрывается «Понятно, начинаем» (`docs/01`, разделы 2, 3 и 14).
- Новый дизайн (26 ноября 2026, решение владельца): тема из примерки по присланному референсу — в приложении, на всех экранах и с таблицей дней эталона: шрифт Inter, фиолетовый акцент, карточки без рамок, кнопки-«пилюли», вкладки — стеклянная панель внизу со значками и «каплей», в мастере — полоса шагов и «Готово на N%». Это слой стилей `app/src/ui/theme.css` поверх `style.css`: разметку экранов он не меняет (кроме полосы шагов мастера), сверка с эталоном его не видит (`docs/01`, раздел 10).
- Что беречь, вес тела, дни подряд (25 ноября 2026, пункты 2, 3 и 6 разбора «Чего не хватает сборке программы»): в онбординге — шаг «Что беречь» на всех трёх путях, перед днями программы (у собранной — после «Цели и времени»), в «Настройке» — та же карточка в свёрнутой части. Больное место (плечо, локоть, запястье, поясница, тазобедренный, колено) ничего не убирает: у упражнений, которые его нагружают, в собранной программе и в списке замен — красная пилюля с названием места, заменить решает атлет (поправка владельца). Стоп-упражнение сборка не ставит и в заменах не предлагает; цель «Силы» и «Гибрида» атлет выбрал сам — она остаётся. На шаге «Веса» — вес тела и сколько раз подряд подтягивания: старт — вес тела, меньше нижней границы диапазона — пока тяга вертикального блока. Дни подряд (вариант владельца «Мышца в одном из двух»): на шаге «Программа» онбординга — над днями программы, которую собрал дневник (просьба владельца тем же днём), — и на «Программе» отмечаются пары соседних дней, в них мышца основная только в одном дне; где так нельзя (три дня подряд из трёх, базовые в обоих днях) — в обоих, с заметкой. Тренерское правило, прямых исследований нет (`docs/03`, разделы 18 и 19; `docs/04`, раздел 3.8, правила 9 и 10). С разминкой во времени (вариант владельца «Цена разминки», 25 ноября 2026) без выбранного времени объём с днями подряд тот же, а с выбранным — сколько влезает: в днях пары мышц и разминок меньше, день вне пары берёт все мышцы; заметка «Дни подряд» об этом говорит.

## Принципы продукта

1. **Дневник не решает за атлета.** План строится по его правилам. Всё, что дневник хочет изменить, — поправка с причиной, которую можно снять. С днями «День N» с 26 ноября 2026 — поправка с причиной строкой плана, без галочки: план выставляет дневник (решение владельца).
2. **У каждого правила есть объяснение.** В текстах честно различаются выводы исследований и тренерские правила.
3. **Числа считаются, а не оцениваются на глаз.** Объём, зоны, время — по формулам из `docs/03-methodology-and-algorithms.md`.
4. **Данные отдельно от кода.** Никаких зашитых в код записей; пустое хранилище — рабочее состояние.
5. **Интерфейс на русском, обращение на «ты»,** без жаргона и без «геймификации».
6. **Не терять ввод.** Идущая тренировка сохраняется автоматически и переживает перезагрузку и смену профиля.

## Словарь

- **Слот** — день программы. В записях это `mon`, `wed`, `fri` и `d4`; на экране приложения — «День 1…4» без привязки к дню недели. В артефакте слотов три, и это понедельник, среда и пятница.
- **Таблица дней эталона** — дни как в артефакте (три дня с днями недели): такой логика видит дни, пока приложение не вызвало `useDays`. На ней идут эталонные тесты и общие сценарии сверки экранов.
- **День вне недели** — день, которого при выбранном числе дней нет (день 3 при двух днях): его записи остаются в журнале, в план он не попадает.
- **Рабочий подход** — подход с числом повторов, не разминочный и не пропущенный.
- **Запас, RIR** — сколько повторов оставалось до отказа.
- **Дробный объём** — недельные подходы на мышцу: прямой подход = 1, косвенный = 0.5; подход с запасом от 3 повторов — за половину.
- **Зоны** — нет нагрузки (0), мало (до 4), ниже рабочей (4–10), рабочая (10–20), выше зоны (больше 20).
- **Базовое** — упражнение с `mode: 'cycle'`. В эталоне оно всегда идёт по процентам от расчётного максимума; в приложении — только в силовой роли, которую ставит цель (сила по запасу, поддержание), а в «Массе» — по двойной прогрессии.
- **Расчётный максимум (TM)** — вес подхода, делённый на процент.
- **Волна** — проценты по неделям: обычная, тяжёлая, поддержание. Только в эталоне и с таблицей дней эталона.
- **Сила по запасу** — режим базового: подходы одним весом, вес на следующую неделю решает запас в последнем подходе. С днями «День N» — тяжёлый день 3×4, с таблицей дней эталона — 4×4.
- **Лёгкий день** — ещё один день базового в силовой роли на фиксированной доле максимума: с днями «День N» — 3×8 на 75%, с таблицей дней эталона — 3×4 на 78%.
- **Средний день** — третий день «Силы: <движение>» с днями «День N»: 3×6 на 79%, отдельное упражнение `<id>_mid`. С 25 ноября 2026 сборка его не ставит: «Сила: <движение>» — два дня.
- **Пауэрлифтерская тройка** — цель «Силы» с днями «День N»: приседания, жим лежа и становая, у каждого тяжёлый и лёгкий день; от трёх дней в неделе.
- **Двойная прогрессия** — сначала растут повторы в диапазоне, потом вес; «независимая» — по каждому подходу отдельно.
- **Поправка** — предложение дневника изменить план, с тегом и причиной.
- **Шаблон дня** — последняя законченная тренировка этого слота или принятая программа, пока по ней в этом слоте не тренировались. С днями «День N» запись дня, которого нет в принятой программе или который в ней пуст, сделанная до её принятия, шаблоном не служит.
- **Мышцы вне расчёта** — мышцы, которым дневник подходы не выделяет и ноль которых не считает пробелом.
- **Снаряд** — место, где лежит упражнение и откуда берётся шаг веса: тренажёр, блок, штанга, гантель, свой или «Без снаряда».
- **Закреплённое упражнение** — упражнение третьего дня пауэрбилдинга; сборка его не убирает и не переносит.
- **Силовой режим** — сборка «Сила: каждое базовое два раза в неделю»: всем базовым программы сила по запасу и лёгкий день, подсобке — уровень ниже рабочей зоны. Только с таблицей дней эталона; с днями «День N» — цели «Силы».
- **Сила в одном базовом** — сборка «Сила: <базовое>»: оно идёт три дня в неделю (тяжёлый день и два лёгких), остальные базовые — раз в неделю, дня «на массу» нет, подсобка — как в силовом режиме. С днями «День N» это «Сила: <движение>»: тяжёлый и лёгкий день (до 25 ноября 2026 — ещё средний), остальные базовые — обычные упражнения.
- **Цель программы** — как на «Программе» выбирается сценарий сборки: масса (поровну или с группой мышц в приоритете), сила (с днями «День N» — тройка или одно движение, с таблицей дней эталона — силовой режим или одно базовое), гибрид (пауэрбилдинг вокруг одного движения), вручную.
- **Встроенный справочник** — список упражнений в коде приложения, с которым открывается профиль без своих упражнений.
- **Онбординг** — мастер первого входа на «Обзоре» пустого профиля (`app/src/ui/onboard.ts`), только с днями «День N».
- **Оценка старта** — стартовый вес упражнения со штангой или гантелями по названному весу похожего (`KIN` в `rules.ts`), пометка «оценка» и «≈».
- **Программа с нуля** — сборка, когда во всех трёх днях пусто: базовые из справочника встают по одному в день сами (с днями «День N» в «Массе» — нет).
- **Больное место** — `care` в настройке: зона, нагрузку на которую дневник показывает красной пилюлей; программу оно не меняет (`ZONES` в `rules.ts`).
- **Стоп-упражнение** — `ex.stop`: его сборка не ставит и в заменах не предлагает.
- **Дни подряд** — `pairs` в настройке: пары соседних дней программы без отдыха между ними; в них мышца основная только в одном дне.

## Эталон: первая версия дневника

- `reference/src`: `core.js` — логика без DOM (114 экспортов). `ui1.js` — состояние, хранилище, профили, маршруты, графики. `ui2.js` — обзор, план и запись тренировки, журнал. `ui_prog.js` — «Программа». `ui_body.js` — карта тела. `ui3.js` — прогресс, мышцы, советы, настройка. `style.css`, `shell.html`. `build.js` склеивает всё в один файл и делает тестовую копию с хранилищем в памяти (`reference/harness.html`).
- Без фреймворков и зависимостей: DOM строится функцией `h()`, страница перерисовывается целиком. Приложение устроено так же.
- Страница жила внутри Claude и получала от него хранилище, запросы к модели и сохранение файлов (`window.claude.use(…)`). В приложении это заменено: хранилище — IndexedDB на устройстве, файл сохраняется обычным скачиванием, запросов к модели нет.
- `reference/tests/test_*.js` — тесты логики, `reference/expected/` — их эталонные выводы на примерных данных. Восемь тестов только печатают вывод, четыре ещё и утверждают.

## Что нельзя сломать

- Формат записи подходов и схема документов: по ним идёт импорт.
- План без принятой программы и без отметок: вывод `test_goal.js` и `test_prog2.js` совпадает с эталонным. Эти тесты сравнивают план с двумя ранними версиями логики (`reference/tests/baseline/`); отличия от них известны и записаны в эталонном выводе строками `DIFF` — новых появляться не должно.
- Правила двойной прогрессии и волны по умолчанию — с таблицей дней эталона. С днями «День N» — методика под цель: роль базового, диапазон по типу, расчётный максимум при смене способа; числа на примерных данных — как в `docs/03-methodology-and-algorithms.md`, раздел 15 (`method.test.ts`, решение владельца 24 ноября 2026).
- Порядок в дне: с днями «День N» сборка расставляет дни черновика по правилам `docs/03`, раздел 15.3, подходы и дни от этого не меняются, сразу после «Принять» она ничего не переставляет; в «Вручную» и с таблицей дней эталона порядок не трогается (`method.test.ts`, решение владельца 24 ноября 2026).
- Дробный счёт объёма и границы зон 4 / 10 / 20.
- Максимум в истории упражнения: с таблицей дней эталона — как у эталона (`вес / процент` у базового, у остальных повторы плюс запас сверх целевого); с днями «День N» — по подходам, лучший подход по Эпли от повторов плюс запас, а расчётный максимум плана, от которого считается вес по проценту, прежний (`method.test.ts`, решение владельца 24 ноября 2026).
- Лимиты 11 и 100 — настройки профиля, а не константы. С экрана приложения они не задаются, но читаются из настройки, как и зоны, запас, волна и мышцы вне расчёта (сценарий «свои лимиты и методика из записей»).
- Встроенный справочник не меняет справочник профиля сам: он подставляется только там, где упражнений нет вовсе, и в хранилище попадает с первым сохранением настройки; всё остальное — по кнопкам и при загрузке копии с экрана, которая дополняет справочник профиля встроенным: «без снаряда» — на снаряды, недостающие — добавляются, своё не меняется, полный справочник — как есть (`starter.test.ts`, сценарии «загрузка копии» и «копия туда и обратно», решение владельца 25 ноября 2026).
- «Равномерно», приоритет и пауэрбилдинг: числа на примерных данных из `data/` совпадают с таблицей в `docs/04-program-builder.md` (`test_even.js`, `test_pb.js`).
- Мышцы вне расчёта после сборки — ровно ноль; упражнения по процентам сборка и кнопки по мышцам не трогают (`test_even.js`). С днями «День N» ноль значит «сборка им подходов не выделяет»: упражнение, где такая мышца основная, сборка не ставит, а косвенные от упражнений, где она помогает, остаются (`rules.test.ts`, решение владельца 23 ноября 2026). Исключение — программа с нуля и базовое в приоритете, которого в программе нет: их сборка ставит сама (решение владельца, 19 ноября 2026).
- Там, где базовые в программе уже стоят, и в справочнике без базовых сборка программы — та же, что у эталона (`scratch.test.ts`, `npm run parity`). Силовой режим на это не влияет: он включается только своим пунктом списка.
- Выбор цели сводится к тем же режимам сборки, что давал список «Как собрать» артефакта: сборки не меняются. Общие сценарии сверки выбирают сценарий помощником `mode`, который знает и список эталона, и кнопки приложения (`npm run screens`).
- Силовой режим: числа на примерных данных из `data/` совпадают с таблицей в `docs/04-program-builder.md`, раздел 3.3а; при трёх базовых — по одному тяжёлому и одному лёгкому в день; без базовых в программе получается «Равномерно» (`strength.test.ts`, с таблицей дней эталона).
- Сила в одном базовом: числа на примерных данных из `data/` совпадают с таблицей в `docs/04-program-builder.md`, раздел 3.3б; выбранное базовое — три дня в неделю, у остальных лёгких дней нет, закреплённого упражнения «на массу» нет (`solo.test.ts`, с таблицей дней эталона).
- Цели «Силы» и «Гибрида» с днями «День N»: числа на примерных данных из `data/` совпадают с таблицей в `docs/04-program-builder.md`, раздел 3.3в; у тройки в каждом дне один тяжёлый и один лёгкий день; цель, которой нет в справочнике, сборка берёт из встроенного, а справочник профиля не переписывает (`targets.test.ts`, решение владельца 24 ноября 2026).
- Дни силовой роли с днями «День N» — «Новая схема»: тяжёлый 3×4 на 83% с решением по запасу, лёгкий 3×8 на 75% (у становой 3×6 на 79%), среднего дня сборка не ставит, у изоляции 3×6 и 3×10 на 71%; расчётный запас во всех днях 2; лёгкий и средний — доля от максимума с первой недели, дальше сдвиг на шаг по своему запасу, «не легче самого лёгкого веса в журнале» — только там, где в вес входит тело (`method.test.ts`, `targets.test.ts`, решение владельца 24 ноября 2026).
- Выводы аудита методики с днями «День N»: предплечья вне расчёта и хват — половина подхода, ягодицы в приседаниях — основные, растянутые варианты раньше, тяжёлый день по запасу в несколько шагов или повторами, лёгкий день по своему запасу, запас 2 со свободным весом, «Проверка запаса», без выбранного времени — одно упражнение вместо двух по два подхода на ту же мышцу в длинном дне, когда баланс недели не хуже (`audit.test.ts`, решение владельца 25 ноября 2026).
- Время на тренировку: без выбора времени экран «Программа» и сборки те же, что у эталона; с выбором — ни одна тренировка черновика не длиннее названного времени по оценке дневника, а числа на примерных данных из `data/` совпадают с таблицами в `docs/04-program-builder.md`, раздел 2 (`fit.test.ts`: с таблицей дней эталона и с днями «День 1…3»); с днями «День N» в дне столько упражнений, сколько помещается во время, но не больше десяти, и при двух днях от 1 ч 30 мин второй день у каждой мышцы (`rules.test.ts`, решения владельца 23 и 25 ноября 2026); в «Массе» и «Гибриде» время заполняется подходами — уровень выше 10, пока дни укладываются, до 12 у остальных при приоритете и до 18 без него, а под «Силой» нет; сразу после «Принять» сборка предлагает ту же программу (`rules.test.ts`, решение владельца 25 ноября 2026); сразу после «Принять» лимит «по времени» не ищется выше принятого (в сценарии «программа: время на тренировку» лимит и программа остаются теми же); с днями «День N» в списке времени — до 2 ч 30 мин, отдых у каждого упражнения свой, разминочные подходы — по типу упражнения и порядку в тренировке, а раскладка разминки — доли первого рабочего веса вниз до шага снаряда (`warm.test.ts`), а дни черновика отличаются по длине не больше чем на 10 минут, когда их можно выровнять (`rules.test.ts`, `targets.test.ts`, просьба владельца 25 ноября 2026).
- Плато по тренду — только с днями «День N»: растущий на 0.5% и 1% в неделю выдуманный атлет не получает ни «Плато», ни «Отката», раз и два раза в неделю, с запасом и без; настоящее плато — вес не снижается: «Плато» просит проверку запаса, с упражнением на те же мышцы в справочнике — замена (выключена, пока атлет её не включит), «Откат» −10% — только при спаде; сразу после снижения веса нового сброса нет; на «неделей позже» в среду десятой недели «Плато» нет, у жима ногами — неделей позже, с пятым подходом вместо −10%; «Мало объёма» — и у стоящего упражнения; статус на «Прогрессе» — по тому же тренду; с таблицей дней эталона — три тренировки без рекорда, как у эталона (`plateau.test.ts`, решение владельца 26 ноября 2026).
- Время по факту и «Не делал два раза» — только с днями «День N»: темп — медиана по последним пяти ответам, от двух, без опечаток, от 0.75 до 1.75; запись без ответа — та же, что у первой версии; перенос, раздача и «убрать» на примерных данных, объём недели после записи в программу тот же, пара сторон — вместе; программа под выбранное время, которая с темпом не влезает, сокращается сама после тренировки — только сокращается, «Вернуть прежнюю» отменяет и больше не сокращает, план с поправками укладывается во время (`skips.test.ts`, сценарий «программа короче, когда не успеваешь», просьба владельца 25 ноября 2026).
- Сценарии с днями «День N»: после каждого шага экран, записи и черновик — как в снимках `app/snapshots/` (`npm run screens -- --дни`, на GitHub — задание «Проверки в браузере: дни «День N»»).
- Дни: с таблицей дней эталона поведение — как у эталона (`npm run parity`, общие сценарии `npm run screens`); при трёх днях «День N» сборки те же, меняются только слова (правила приложения из `rules.ts` в этой проверке выключены); прежние записи при любом числе дней не меняются и читаются; вернувшись к большему числу дней, атлет не получает прежний день поверх принятой программы, и базовое не встаёт дважды; при двух днях первое предложение сборки не слабее того, что она даёт сразу после принятия; в «Гибриде» в дне не больше одного базового по процентам: лишнее уходит с заметкой, жертву выбирает атлет, при том же числе дней сборка предлагает ту же, а при большем убранное возвращается в день без другого базового (решение владельца 23 ноября 2026); числа для двух и четырёх дней на примерных данных из `data/` совпадают с таблицей в `docs/04-program-builder.md`, раздел 3.7 (`days.test.ts`).
- Шаг веса — только от снаряда; поля `step` и `round` в старых данных не читаются (`test_gear.js`).
- Оценка стартового веса по похожему упражнению — только с днями «День N», только штанга и гантели одной семьи, только от тяжёлого к лёгкому, меньшая из оценок; своё названное и журнал важнее; с таблицей дней эталона известные веса — как у эталона (`onboard.test.ts`, решение владельца 25 ноября 2026). Онбординг — только в приложении с днями «День N» и только пока в профиле нет ни тренировок, ни программы (сценарии «пустой дневник» и «онбординг: …»).
- Что беречь и дни подряд — только с днями «День N»: пилюли больных мест сборку не меняют; стоп-упражнения сборка не ставит и в заменах не предлагает, а цель «Силы» и «Гибрида» остаётся; в двух днях подряд мышца основная только в одном, у каждой мышцы от двух дней, без выбранного времени объём тот же, с выбранным — дни укладываются в него, сразу после «Принять» сборка предлагает ту же программу; три дня подряд из трёх — как без отметки; с таблицей дней эталона `care`, `pairs` и `stop` не читаются (`care.test.ts`, решение владельца 25 ноября 2026).
- Известные веса действуют, только пока упражнения нет в журнале (`test_known.js`).
- Сила по запасу: запас 2+ — плюс шаг, 1 — тот же вес, 0 или не закрыл — минус 5% (`test_pb.js`, в приложении — `method.test.ts`).
- Раздельность данных профилей.
- Примерные данные равны выводу генератора (`npm run sample`), а в проекте нет ничего личного (`npm run leaks`).

## Команды

Эталон (из корня проекта):

- Эталонные проверки логики: `node reference/run-checks.js`; ключ `--update` переписывает эталонные выводы — только после намеренной смены примерных данных или тестов эталона, и перед ним старые файлы `reference/expected/*.txt` нужно удалить (упавший тест при `--update` пропускается, и его старый вывод остался бы на месте).
- Посмотреть эталон в браузере: открыть `reference/harness.html` (`?p2` — два профиля, `?empty` — пустой дневник). После смены примерных данных файл пересобирается: скопировать `reference/.check/dist/harness.html`.
- Примерные данные: `node data/make.cjs --check` — файлы в `data/` совпадают с выводом генератора; без ключа — переписать файлы.

Приложение (из папки `app/`; нужен Node.js 22.18 или новее — он запускает `.ts` без сборки):

- Установка: `npm install`
- Запуск для разработки: `npm run dev` — http://localhost:5173, пересборка при правке исходников. В Claude Code то же самое — предпросмотр `dnevnik` из `.claude/launch.json` (на Windows, где `node` нет в PATH, — `dnevnik-windows`).
- Готовая сборка: `npm run build` — в `app/dist` (страница, один файл кода, стили, шрифты, значки, работа без сети); в выводе — версия сборки, она же видна в приложении в «Настройке» → «Данные». Посмотреть сборку: `npm run preview` — http://localhost:5174.
- Все проверки без браузера: `npm run check`. Это пять шагов подряд:
  - `npm run sample` — файлы в `data/` совпадают с выводом генератора `data/make.cjs`;
  - `npm run typecheck` — типы, строгий режим (`tsc --noEmit` для кода и для тестов);
  - `npm run tokens` — код `src/core` и `src/ui` без типов совпадает с эталоном токен в токен, стили — строка в строку; всё, что изменено, убрано или добавлено намеренно, перечислено в самом скрипте с причиной;
  - `npm run parity` — эталонные тесты логики на `src/core` дают вывод из `reference/expected/`;
  - `npm run unit` — тесты `app/tests/`: хранилище, резервная копия, расчёты после импорта, прослойка для экранов, встроенный справочник упражнений, программа с нуля, силовой режим, сила в одном базовом, выбор цели и время на тренировку на «Программе», дни «День 1…N», методика под цель, порядок в дне цели «Силы» и «Гибрида» с днями новой схемы, выводы аудита методики, оценка стартового веса по похожему упражнению, программа текстом, что беречь и дни подряд, поправка «Не делал два раза» и время по факту, разминка, плато по тренду и что делать при плато. Пропущенных тестов быть не должно.
- Сверка экранов в работе: `npm run screens` (нужен Chrome или Edge; все сценарии — около 15 минут). Эталонная страница и приложение получают одни и те же записи и проходят одни и те же шаги из `app/scripts/scenarios.mjs`: нажать, ввести, выбрать. После каждого шага должны совпасть разметка экрана символ в символ, значения в полях, сообщение, сохранённые записи, черновик, сохранённый файл; ошибка страницы или страница шире экрана — провал. Общие сценарии идут на двух наборах примерных данных: основном и «неделей позже» (`data/later.json`). Намеренные отличия — в списке `KNOWN` скрипта.
  - часть сценариев: `npm run screens -- журнал мышцы` (по словам из названия), один набор записей: `npm run screens -- "журнал · примерные"`;
  - `-- --шаги` показывает, что изменил каждый шаг; `-- --кнопки` — что есть на экране там, где сценарий остановился;
  - `-- --шрифт-айфона` даёт приложению размер шрифта в полях, как на iPhone: так проверка «страница не шире экрана» видит то, что увидит телефон.
  - `-- --дни` проходит все сценарии в одном приложении с его днями «День 1…N», без сравнения с эталоном: общие сценарии сверяются с эталоном на таблице дней артефакта, а этот запуск проверяет методику и экраны приложения. После каждого шага то же, что сравнивается с эталоном (адрес, разметка, шапка, поля, сообщение, сохранённые записи, черновик, файл, буфер), сверяется со снимком в `app/snapshots/` — по текстовому файлу на сценарий и набор записей; отличие от снимка — провал, а что получилось вместо него, лежит в `app/.snapshots/` (на GitHub — в приложенном к прогону файле `snapshots-now`). Около 10 минут.
  - `-- --переписать` — тот же прогон, но снимки пишутся заново: только когда приложение изменено намеренно. С названиями сценариев переписываются только их снимки; без названий — все, а снимки убранных сценариев удаляются. Как устроен снимок — `app/scripts/snapshots.mjs`.
- Работа без сети: `npm run offline` (нужен Chrome или Edge). Готовая сборка раздаётся так же, как на GitHub Pages — в подпапке адреса и с кэшем на 10 минут. Она открывается в браузере, раздача выключается — приложение должно открыться снова с записями, стилями и шрифтами; потом проверяется, что изменённая сборка доходит до браузера целиком.
- Нет ли в проекте личного: `npm run leaks` — файлы под git и ещё не добавленные; `npm run leaks -- --история` — ещё и все прежние версии файлов в истории ветки. Смотрит имена файлов, адреса почты, пути, ключи. На компьютере, где в `private/data` лежат настоящие записи, сверяет с ними весь проект; в облаке этой папки нет, и проверка об этом говорит.
- Проверка выложенного сайта: `npm run live` (нужен Chrome или Edge и сеть), на том же коммите, что лежит в `main`. Адрес из `app/deploy/site.json` отдаёт ту же версию и те же файлы, что сборка из исходников; приложение открывается на ширине телефона и ещё раз — без сети; в коммитах репозитория нет настоящих адресов почты.
- Браузер для проверок берётся из переменной `CHROME_PATH`, затем `CHROME_BIN`, затем из обычных мест установки Edge и Chrome и только потом из `BROWSER`. Эталонная страница берёт шрифты с fonts.googleapis.com и fonts.gstatic.com: сверке экранов нужен доступ к этим адресам.

Команды выкладки нет: сайт собирает и публикует GitHub из ветки `main` (`.github/workflows/site.yml`, `docs/07-deploy-and-phone.md`).

## Как устроено приложение

- `app/src/core/` — логика без DOM на TypeScript: 19 модулей (`sets`, `plan`, `adapt`, `program`, `insights` и другие), типы данных в `types.ts`, прежний набор из 114 функций — объект `Core` в `index.ts`. Новое, чего в эталоне нет: `starter.ts` — встроенный справочник упражнений (данные и их выборка, расчётов нет), `strength.ts` — числа силового режима, списки целей «Силы» и «Гибрида» и дни силовой роли (тяжёлый, средний, лёгкий), `days.ts` — таблица дней «День 1…N», их число и то, что стоит в днях вне недели, `paste.ts` — разбор программы, вставленной текстом в онбординге (дни, подходы, сверка названий; расчётов нет), `pace.ts` — темп атлета по времени, названному в конце тренировок, `skips.ts` — поправка «Не делал два раза» (что делать с упражнением, которое не успевают), и `rules.ts` — правила приложения, которых нет в эталоне и которые действуют с днями «День N» (румынская тяга, время на тренировку и длина дня, заполнение времени подходами и число упражнений в тренировке, методика под цель: роль базового, диапазон по типу, расчётный максимум при смене способа; порядок упражнений в дне; оценка стартового веса по похожему упражнению — `KIN`; больные места, стоп-упражнения и дни подряд — `ZONES`, `stopOf`, `pairSplit`; разминка по типу упражнения и её раскладка — `WARM`, `warmSets`, `warmPlan`; плато по тренду без каскада, что делать при плато и статус по тренду — `PLATEAU`, `plateauOf`, `cutAsk`, `statusOf`; тем же выключателем `appRules` в `program.ts` включено одно базовое в тренировке); в `Core` они не входят.
- `app/src/store/` — хранилище документов: `store.ts` (пути, подписки), `idb.ts` (IndexedDB на устройстве), `memory.ts` (в памяти, для проверок).
- `app/src/data/` — данные дневника поверх хранилища: пути профилей, список профилей, загрузка профиля в логику (`load.ts`), резервная копия (`backup.ts`). Описание — `docs/02-data-model.md`, раздел 9.
- `app/src/ui/` — экраны. 17 модулей — это интерфейс артефакта, разрезанный по смыслу без изменения кода (`dom`, `state`, `storage`, `render`, `charts`, `overview`, `workout`, `journal`, `program`, `bodymap`, `progress`, `muscles`, `coach`, `setup`, `toast`, `views`, `main`): к коду добавлены только типы, и он проверяется в строгом режиме. Новое: `types.ts` (типы экранов: состояние страницы, элементы, черновики, графики), `platform.ts` (то, что раньше давал Claude: хранилище теми же вызовами, сохранение файла; запросов к модели нет), `importer.ts` (загрузка резервной копии с экрана), `device.ts` (что видно про устройство: закреплены ли записи, установлено ли приложение, версия), `starter.ts` (кнопки встроенного справочника в «Настройке»: разложить по снарядам, добавить типовые, убрать неиспользуемое), `goal.ts` (выбор сценария на «Программе»: кнопки цели и уточняющий список), `fit.ts` (лимит недели от времени на тренировку), `draft.ts` (черновик сборки программы: его считают и «Программа», и онбординг), `onboard.ts` (онбординг: мастер первого входа), `builtday.ts` (день программы, которую собрал дневник: только «Заменить» — в онбординге и на «Программе» с днями «День N»), `care.ts` (что беречь и дни подряд: в онбординге, на «Программе» и в «Настройке»), `skipfix.ts` и `pace.ts` (поправка «Не делал два раза» и время по факту на экране тренировки), `trim.ts` (программа короче, когда тренировки не влезают в выбранное время), `warmup.ts` (раскладка разминки в карточке упражнения), `smooth.ts` (экран не «моргает» при нажатии), `flipmap.ts` (фигура мышц — карточка, которая переворачивается), `marks.ts` (значки зон мышц с легендой и строка упражнения в журнале с отметкой тренировки), `carousel.ts` (карусель карточек: дни программы в онбординге и на «Программе», группы мышц на «Мышцах»), `memo.ts` (памятка: последний шаг онбординга и экран в начале тренировки), `theme.css` (новый дизайн: слой стилей поверх `style.css`) и `tabdrop.ts` («капля» в нижнем меню), `pwa.ts` и `sw.js` (работа без сети), `index.html`, `style.css`, `manifest.webmanifest`, `icons/`.
- `app/tests/` — тесты (`node --test`); `app/scripts/` — сборка (`build.mjs`, `dev.mjs`, `serve.mjs`) и проверки (`tokens.mjs`, `parity.mjs`, `screens.mjs` со сценариями в `scenarios.mjs` и снимками дней «День N» в `snapshots.mjs`, `offline.mjs`, `live.mjs`, `leaks.mjs`; браузер для проверок — `browser.mjs`). `app/snapshots/` — снимки прогона `npm run screens -- --дни`: их пишет только `--переписать`, руками не правятся.
- `app/deploy/site.json` — адрес сайта и репозиторий.
- `data/` — примерные данные, на которых идут все проверки: атлет выдуман, файлы пишет генератор `data/make.cjs` (первая тренировка каждого дня — таблицей, дальше план строит логика эталона, а повторы считает формула генератора; случайных чисел нет). `workouts.json` и `config.json` — первый профиль, записанный «по-старому»; `config.p2.json` и `config.p2.stored.json` — второй профиль; `later.json` — тот же дневник неделей позже, резервная копия с запасом в подходах, весом тела и принятой программой. Описание — `docs/02-data-model.md`, раздел 6.
- `.github/workflows/site.yml` — проверки на отправку в `main` и в пробную ветку `try/…` и на каждый запрос на слияние (три задания одновременно: без браузера; в браузере — работа без сети и сверка с эталоном; в браузере — сценарии с днями «День N» и снимки); публикация сайта из `main`. Отправка в ветку с другим именем проверок не запускает, пока на неё не открыт запрос на слияние.

Тесты эталона (`reference/tests`), их выводы (`reference/expected`), `reference/harness.html` и `data/` меняются только вместе и только намеренно: сменились примерные данные или тест эталона — выводы переписываются кодом эталона (`--update`), а не руками. Не править их, чтобы прошёл тест приложения.
- Примерные данные меняются только через генератор `data/make.cjs` и отдельным коммитом. Вместе с ними обновляется всё, что на них посчитано: эталонные выводы, `reference/harness.html`, числа в `app/tests` и в сценариях, таблицы в `docs/04` (разделы 2, 3.2, 3.3а, 3.3б, 3.7) и примеры в `docs/03`, раздел 12. Числа берутся из запуска, а не на глаз. Пороги в тестах (разброс, доля приоритета, «не больше одной мышцы с одним днём») под данные не подгоняются: если данные их не держат — это вопрос владельцу.
- Расчёт в `app/src/core/` совпадает с эталоном, кроме намеренных изменений. Намеренное изменение правила вносится в список `ALLOW_CORE` в `app/scripts/tokens.mjs` с причиной и только после согласия владельца.
- Экран менять можно, но каждое отличие от первой версии записывается с причиной: изменённая функция — в `ALLOW_UI`, убранная — в `GONE_UI`, строка стилей — в `ADDED_CSS` (всё в `app/scripts/tokens.mjs`); видимое отличие разметки — в `KNOWN` в `app/scripts/screens.mjs`; строка — в таблице `docs/01-product-and-ui.md`, раздел 14.
- Новое действие на экране — шаг в `app/scripts/scenarios.mjs`. Шаг, после которого в приложении ничего не изменилось, считается ошибкой сценария.
- Изменение, которое намеренно меняет экран или записи с днями «День N», идёт вместе с перезаписью снимков (`npm run screens -- --переписать`) в том же запросе на слияние, а в его описании сказано, что поменялось в снимках и почему. Снимок не переписывается, чтобы прошла проверка: отличие, которого не ждали, — ошибка, её ищут в коде.
- Код экранов пишется с типами, без `// @ts-nocheck` и `@ts-ignore`. Пока экран совпадает с эталоном, в нём можно добавлять только то, что исчезает при сборке: типы, `as`, `!`. `any` — только на стыках, перечисленных в `docs/05-features-and-backlog.md`, раздел 2.
- Любое изменение правила расчёта — вместе с тестом и строкой в `docs/03-methodology-and-algorithms.md` с пометкой, откуда правило: методика по умолчанию, исследование, тренерское правило.
- Правила из разделов «Методика по умолчанию» и «Решения владельца» менять только после прямого согласия владельца.
- Новая функция — строка в таблице `docs/05-features-and-backlog.md` с критерием готовности.
- Перед тем как назвать задачу сделанной, запусти проверки и посмотри на экран в браузере на ширине телефона (390 px): горизонтальной прокрутки быть не должно.
- Когда задача сделана и проверки пройдены — коммит с понятным описанием по-русски. Коммит — только в состоянии, где `npm run check` и `node reference/run-checks.js` проходят.

## Личное и открытый репозиторий

Решение владельца (20 ноября 2026): исходники и сайт лежат в одном открытом репозитории `stanleyjesus/dnevnik`, работа идёт в облачных сессиях, а всё личное из проекта убрано полностью — записи тренировок, настройки профилей, всё, что на них посчитано, и рассказ о людях. Все проверки идут на примерных данных: личная история отражает личную методику и для продукта не показательна.

Что это значит в работе:

- В репозиторий, в тесты, в примеры документов, в чат и в облачную сессию не попадают настоящие записи и резервные копии дневника. Импорт и всё остальное отлаживается на примерных данных; нужен новый случай — он добавляется в генератор.
- Личным считается: записи тренировок и вес тела, настройки профилей (программа, названные веса, свои снаряды, текст методики), заметки, имена профилей и людей, числа и даты, посчитанные на таких записях, пересказ разговоров. Личным не считается: правила продукта и методика по умолчанию (волна 77 → 82 → 87 зашита в код как умолчание), встроенный справочник упражнений с его основным набором, слово «владелец» как роль того, кто принимает решения, имя учётной записи в адресе сайта.
- Примерные данные лежат в другом году, чем настоящий дневник: ни одна дата в проекте не совпадает с датой настоящей тренировки. Часы проверок стоят на среде десятой недели примерного журнала.
- `npm run leaks -- --история` проходит перед каждой отправкой. В облаке он проверяет имена файлов, почту, пути и ключи; сверка с настоящими записями возможна только на компьютере владельца, где они лежат в `private/data` (в git эта папка не входит).
- Коммиты подписываются только скрытым адресом GitHub (`…@users.noreply.github.com`), соавтор Claude — `noreply@anthropic.com`. Адрес автора в открытом репозитории виден всем и не стирается без переписывания истории: перед первой отправкой из нового места проверь `git config user.email`.
- Обновить сайт — значит слить изменение в `main`: дальше проверки и публикацию делает GitHub. Сливает Claude сам, когда владелец принял содержание изменения и все проверки прошли — на запросе на слияние в GitHub и `npm run screens -- --дни`; о слиянии он пишет владельцу после (решение владельца 24 ноября 2026; до него нужно было согласие на каждое слияние). Смена истории `main` и настройки репозитория — только с согласия владельца.

Публикация (23 ноября 2026, с согласия владельца на каждый шаг):

## Как общаться с владельцем

- По-русски, коротко, сначала итог. Длинных текстов не нужно ни в ответах, ни на экране.

## Открытые решения — их принимает владелец

- Перенос записей между телефоном и компьютером: только файлом резервной копии или нужна синхронизация.
- Импорт резервной копии сейчас заменяет все записи; нужен ли режим «дополнить».
- Отдельный вход для каждого профиля или по-прежнему один человек на все профили.
- Наблюдения о сборке на примерных данных: менять ли поведение (`docs/05-features-and-backlog.md`, раздел 4).
- Лицензия открытого репозитория: сейчас её нет — код можно читать, но права на него не передаются.
- Пять и больше тренировочных дней: сейчас их два, три или четыре.
- Насколько приоритет выше остальных: сейчас коэффициент 1.5 зашит (`PRIO_K`).
- Вопросы по методике без ответа — в `docs/05-features-and-backlog.md`, раздел 4.
