# Тренировочный дневник

Дневник силовых тренировок: веб-приложение, которое ставится на телефон и работает без сети. Записи лежат только на устройстве, в браузере; на сервер ничего не уходит, запросов к нейросети нет.

Приложение: https://stanleyjesus.github.io/dnevnik/

Что оно делает:

1. Хранит тренировки: упражнения, подходы, вес, повторы, запас до отказа.
2. Строит план следующей тренировки по правилам атлета и предлагает поправки с объяснением.
3. Считает недельную нагрузку по мышцам и показывает, что отстаёт.
4. Собирает и перестраивает программу под цель в рамках лимитов атлета.

## Что где лежит

| Путь | Что это |
|---|---|
| `app/` | Приложение: TypeScript без фреймворков. `src/core` — логика без экрана, `src/store` и `src/data` — хранилище и резервная копия, `src/ui` — экраны; `tests/` — тесты, `scripts/` — сборка и проверки |
| `reference/` | Эталон: исходный код первой версии дневника (она была одной страницей), её тесты логики и их эталонные выводы. Приложение сверяется с ним — логика токен в токен, экраны шаг за шагом |
| `data/` | Примерные данные, на которых идут все проверки. Атлет выдуман: файлы пишет генератор `data/make.cjs` |
| `docs/` | Продукт и экраны, модель данных, методика и алгоритмы, сборка программы, список функций, выкладка и телефон |
| `CLAUDE.md` | Контекст проекта для Claude Code: решения, правила, словарь, что нельзя сломать, команды |
| `.github/workflows/site.yml` | Проверки на отправку в `main`, в пробную ветку `try/…` и на запрос на слияние; публикация сайта из ветки `main` |

Документы описывают, что и почему; код — как именно. При расхождении прав код.

## Запуск и проверки

Нужен Node.js 22.18 или новее (он запускает `.ts` без сборки). Команды — из папки `app/`.

```bash
npm install
npm run dev        # приложение для разработки: http://localhost:5173
npm run check      # все проверки без браузера
npm run screens    # сверка экранов с эталоном в браузере (нужен Chrome или Edge), около 15 минут
npm run screens -- --дни   # те же сценарии с днями «День 1…N», сверка со снимками в app/snapshots/ (переписать: -- --переписать)
npm run offline    # работа без сети и обновление сборки
npm run build      # готовая сборка в app/dist
```

`npm run check` — это пять шагов: примерные данные совпадают с выводом генератора; типы в строгом режиме; код логики и экранов совпадает с эталоном токен в токен, кроме намеренных изменений, перечисленных в `app/scripts/tokens.mjs`; эталонные тесты логики дают на коде приложения вывод из `reference/expected/`; тесты приложения.

Эталон сам по себе: `node reference/run-checks.js` из корня. Посмотреть эталонную страницу — открыть `reference/harness.html` в браузере с диска (`?p2` — два профиля, `?empty` — пустой дневник).

## Примерные данные

В `data/` нет ни одной настоящей записи. Журнал, настройки двух профилей и резервная копия «неделей позже» считаются генератором `data/make.cjs` по таблицам и формулам из него самого, без случайных чисел: запуск всегда даёт те же файлы.

```bash
node data/make.cjs --check    # файлы в data/ совпадают с выводом генератора
node data/make.cjs            # переписать файлы
```

Менять примерные данные — только через генератор и отдельным коммитом: вместе с ними меняются эталонные выводы (`node reference/run-checks.js --update`), числа в тестах приложения и таблицы в `docs/04-program-builder.md`.

## Личных записей здесь нет

Репозиторий открытый. Настоящие тренировки, настройки профилей и резервные копии дневника в него не кладутся — ни в файлы, ни в тесты, ни в примеры в документах. Проверка:

```bash
npm run leaks -- --история
```

Она смотрит имена файлов, адреса почты, пути и ключи во всех файлах и во всей истории ветки. На компьютере, где в папке `private/data` (в git она не входит) лежат настоящие записи, она ещё и сверяет с ними весь проект.

## Сайт

Сайт собирает и публикует GitHub из ветки `main`: сначала все проверки, потом сборка и GitHub Pages. Проверить, что адрес отдаёт сборку этого коммита и открывается без сети: `npm run live`. Подробности и установка на телефон — `docs/07-deploy-and-phone.md`.
